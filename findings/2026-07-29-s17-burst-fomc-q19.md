## 4. Cross-venue dislocation scan — the fee model changes the answer, and none of the answers is an edge

### 4a. The fee bug, confirmed and EV-relevant in both directions

Before this run, `_best_dislocation` / `build_burst_report` charged the Polymarket leg a **flat**
per-contract `--poly-fee`, default **0.0**. The real schedule is
`core.pricing.polymarket_fee_per_contract(price, rate) = rate·p·(1−p)` with **no cent round-up** (Fee
Structure V2; `POLYMARKET_US_TAKER_RATE = 0.05`), i.e. **$0.0125 at p=0.50, not $0.05**. So:

- the shipped `0.0` default **under-charged** — a fee-bearing leg booked free, which manufactures phantom
  dislocations (the prime-directive failure mode); and
- a naive flat `0.05` **over-charges ≈4×** at mid prices — the L5 maker/taker mistake in mirror image.

The sibling WC-schema probe `scripts/s9_leadlag_probe.py` was corrected to the rate-based schedule on
2026-07-15 (Q31) and the WC-semi2 finding's own lesson candidate said the fee "must be a rate, not a flat
constant" — **that fix was never propagated to the Fed-schema module.** Fixed here. The executed runs

## Lesson candidates (for the kb-distiller)

1. **A per-venue fee must be a SCHEDULE FUNCTION, never a flat per-contract constant — and a fee fix applied
   to one probe must be propagated to its sibling schemas the same run.** `scripts/s17_leadlag_probe.py`'s
   burst mode charged the Polymarket leg a flat `--poly-fee` (default **0.0**) for 16 days after
   `scripts/s9_leadlag_probe.py` was corrected to `core.pricing.polymarket_fee_per_contract` (Q31,
   2026-07-15) — and the WC-semi2 finding's own lesson candidate had already written the rule ("must be a
   rate, not a flat constant"). The stale flat parameter is wrong in **both** directions: `0.0` under-charges
   and manufactures phantom dislocations (prime-directive failure), a naive flat `0.05` over-charges ~4× at
   mid prices (`0.05·p·(1−p) = $0.0125` at p=0.50, not $0.05 — the L5 maker/taker error mirrored). Executed
   on this window the three views give **0 / 34 / 49** fee-clearing captures, so the parameter was
   load-bearing on the verdict, not cosmetic. Family L5/L18. Enforcement candidate: extend
   `no_handrolled_fee_rate` to flag a *flat per-contract fee parameter* named `*_fee` that is subtracted from
   a P&L without passing through a schedule function — the current invariant only catches banned rate
   literals, and a flat `0.0` default trips nothing.

   meaningless against a near-zero denominator.** `leadlag_stability()` labelled `KXFEDDECISION-26SEP-H0`

   leads survives leave-one-out", i.e. the artifact was promoted to the headline. Fixed with a named
   `LEADLAG_RHO_MAGNITUDE_FLOOR` (= the module's own `LEADLAG_SIGNED_LEADER_MARGIN`, so the gate is derived
   from the code rather than fitted to the data) and a distinct `UNSTABLE_below_magnitude_floor` verdict
   checked BEFORE sign and retention. Generalises: **any ratio-based robustness check needs an absolute-
   magnitude precondition on its denominator**, and the inflated ratio should be reported alongside the
   rejection so the pathology is legible. Sibling: a "leader" declared by comparing two NEGATIVE lag-ρ's

   invocation; it responded by proving the fee bug from source, deriving the dislocation result by hand with
   an exhaustiveness bound, computing nothing it could not bound (no ρ was quoted), and labelling the number
   classes in the document header. Round 2's execution then reproduced the hand-derived `schedule` headline
   **exactly** (34 captures / 5 episodes / +$0.00822, to the float). Two rules fall out: (i) a hand
   derivation with a stated exhaustiveness bound is a legitimate interim deliverable and is worth checking
   against execution afterwards — the agreement is real evidence about both; and (ii) a mid-run
   `git reset --hard` by an orchestrating session silently destroys a worker's uncommitted edits, which cost
   this milestone a full redo cycle — **a worker should commit locally before any long read-only stretch**,
   and re-verify `git diff --stat` after one.
